# Antislop audit 001 — 2026-11-10

Scope: the denim/scrapbook redesign of the photobooth web app (`web/index.html`, `web/style.css`, `web/app.js`), checked against the reference moodboard (denim pocket, polaroid collage, "HOW I KEEP MY WHIMSY" yellow tag, stars, paperclips) and against the antislop core + UI checklist. Verified by reloading the live preview at desktop (1440x900) and mobile (375x812) and comparing every screen (home, camera/effects, templates, email).

Mode: AFTER (audit only). Nothing below has been changed. Reply with the numbers you want fixed.

## HIGH — Hard Gate (R-02, R-25)

### 1. Em dash in shipped UI copy — `R-02`
`web/app.js` has three user-facing strings using `—`:
- L215: `"Face tracker failed to load (needs internet) — effects won't show."`
- L230: `"Camera blocked — allow camera access and reload."`
- L323: `` `Tap your photos in the order you want — picked ${picked.length} of ${n}` ``

Pre-existing text, not introduced by the redesign, but still a live Hard Gate violation. **Fix:** replace each `—` with a period or colon, e.g. `"Camera blocked. Allow camera access and reload."`

### 2. Contrast failure on the email screen's eyebrow text — `R-25`
`#email .eyebrow` renders `var(--muted)` (`#6b6052`) directly on the raw denim background (`#bfddf0`, no card behind it). Measured ratio: **4.33:1**, fails the 4.5:1 normal-text threshold (the text is 20.8px/400-weight, which does not qualify as "large text"). Confirmed with the contrast checker.

Related latent issue: the general `.eyebrow` rule (unused elsewhere right now) sets `color: var(--denim-deep)` (`#5f8ab3`) on `--bg`, which measures **2.57:1** — fails even the large-text floor. It's dead today only because `#email .eyebrow` overrides it; if any other screen reuses the bare `.eyebrow` class, it ships an automatic contrast fail.

**Fix:** darken the eyebrow/caption color (e.g. a muted ink around `#4a4340` on `--bg` passes ~6:1), and fix it at the shared `.eyebrow` rule rather than only in the `#email` override so it can't regress.

## MEDIUM — Purpose-Gate & consistency (this is the "standards not replicated across the page" complaint)

### 3. Brand/hero logo card still wears the old theme — `R-20`, `R-31`
The "Sunway Robotics Club" card (`.brand` / `.hero-logo`) is the one surface that never got the sticker treatment: soft grey drop shadow instead of the hard black offset shadow (`--pop`), thin purple-tinted border around the artwork instead of the 3px black sticker border, no rotation-on-hover language, no tape/pin accent. Every other card on the page (template cards, fx tiles, panels, steps pills) now speaks the same "cream card + black border + offset shadow" language — the logo card is the one holdout, which is exactly the inconsistency being flagged. **Fix:** apply the same `--pop` shadow + black border treatment to `.brand`/`.hero-logo`, or pin it under a washi-tape strip like the template cards.

### 4. Decorative filmstrip belts introduce an off-palette pink — `R-29`, `R-20`
The two scrolling belts on the home screen (`.tracks` / `.lane` / `.belt`) tile real template preview images, two of which (the floral/pink templates) carry pink washi borders and floral illustration color that do not appear anywhere else in the UI. The declared palette everywhere else is denim blue + cream/paper + yellow + one rotating accent per step chip (blue/mint/coral). The belts quietly add a fifth-plus hue with no connection to the rest of the identity, pushing the page past the 2-3-core-plus-1-accent cap. **Fix:** either restrict the belt tiles to templates that stay within the established palette, or desaturate/tint the belt images to the denim/cream family so they read as texture, not as a competing color system.

### 5. Reference's signature motifs (stars, paperclips) are not used as a repeated identity motif — Part 3 (identity motif), `R-20`
The reference's whole visual identity rests on repeated scrapbook gestures: paperclips pinched on photo corners, scattered stars across the background, the yellow banner tag. The current build only has one small washi-tape nub (`.tpl::before`) and a star/star+white-star background texture tiled faintly behind everything. There's no paperclip motif anywhere (templates, photo thumbnails, the hero collage), so the page reads as "denim-and-yellow sticker UI" rather than the specific scrapbook/whimsy concept shown in the moodboard. **Fix:** add a small reusable paperclip accent (SVG, not emoji) to polaroid-style elements (`.tpl`, `.shot`, `.fx`) so the motif repeats the way it does in the reference, and make sure it's the same accent everywhere it appears (not a new shape each time).

## LOW — quality locks / cleanup

### 6. Dead duplicate `font-size` declaration — `R-31`
`#email .eyebrow` declares `font-size: 1.05rem;` and then `font-size: 1.3rem;` two lines later in the same rule block. The first is dead and the rule reads like it was patched rather than authored. **Fix:** delete the first declaration.

### 7. Leftover dead code from the previous (purple) theme
`.lens` and its `spin`/`bob` keyframes are still defined and forced to `display: none`. Not visible, not a slop pattern on its own, but it's unused weight left over from the prior redesign. **Fix:** delete `.lens` and the now-unused `spin` keyframe (bob is still used by `.envelope`, keep that one) next time the file is touched.
